# Switching vs Routing

**Switching** = moving traffic within the same network/VLAN.
**Routing** = moving traffic between different networks/subnets.

## Switching vs Routing

| | Switching | Routing |
|---|---|---|
| OSI layer | Layer 2 | Layer 3 |
| Uses | MAC addresses | IP addresses |
| Connects | Devices in same network/VLAN | Different networks/subnets |
| Main device | Switch | Router / Layer-3 switch |
| Example | 192.168.1.10 → 192.168.1.20 | 192.168.1.10 → 10.10.20.10 |
| Key table | MAC address table | Routing table |
| Linux commands | `ip neigh`, `bridge` | `ip route`, `ip rule` |

## Example

Suppose:

- Server A: `192.168.10.10/24`
- Server B: `192.168.10.20/24`
- Server C: `192.168.20.10/24`
- Gateway: `192.168.10.1`

### A → B

Both are in `192.168.10.0/24`.

```
Server A
   ↓
 Switch
   ↓
Server B
```

This is primarily **switching**.

### A → C

They are on different subnets:

```
Server A
   ↓
 Switch
   ↓
Gateway / Router
   ↓
Server C
```

This requires **routing**.

## Linux Commands

Linux isn't normally your Layer-2 switch, but you can inspect both the routing and neighbour/MAC information from a server.

### 1. Check IP address

```bash
ip addr
# or
ip -br addr
```

Example:

```
eth0    UP    192.168.10.10/24
```

### 2. Check routing — most important

```bash
ip route
```

Example:

```
default via 192.168.10.1 dev eth0
192.168.10.0/24 dev eth0 proto kernel scope link src 192.168.10.10
10.10.20.0/24 via 192.168.10.1 dev eth0
```

This tells you:

- Local subnet → directly connected
- Remote subnet → send to gateway
- Default traffic → send to default gateway

### 3. Ask Linux exactly how it will route traffic

This is an excellent interview command:

```bash
ip route get 10.10.20.15
```

Example:

```
10.10.20.15 via 192.168.10.1 dev eth0 src 192.168.10.10
```

> "I use `ip route get` to determine which interface, source IP, and next hop Linux will use to reach a particular destination."

### 4. Check ARP / neighbour table

```bash
ip neigh
```

Example:

```
192.168.10.1  dev eth0 lladdr 00:11:22:33:44:55 REACHABLE
192.168.10.20 dev eth0 lladdr aa:bb:cc:dd:ee:ff STALE
```

This is useful for understanding Layer 2 connectivity — it maps IP address → MAC address.

### 5. Check network interfaces

```bash
ip link
```

Look for interface state flags:

- `UP`
- `DOWN`
- `LOWER_UP`

Example:

```bash
ip link show eth0
```

### 6. Check VLAN configuration

If VLANs are configured on the Linux host:

```bash
ip -d link show
```

You may see interfaces like:

```
eth0.100
eth0.200
```

You can also use, if Linux bridge/VLAN configuration is involved:

```bash
bridge vlan show
```

### 7. Check the path to a destination

```bash
traceroute 10.10.20.15
# or
tracepath 10.10.20.15
```

This is mainly useful for Layer 3 routing troubleshooting.

### 8. Check connectivity

```bash
ping 10.10.20.15
```

Remember: ping tests ICMP, not the application port. For an application on port 443:

```bash
nc -zv 10.10.20.15 443
```

## Interview Scenario

**Interviewer:** *"Server 10.10.10.20 cannot connect to 10.20.10.30. How do you determine whether it is a switching or routing problem?"*

**Strong answer:**

> First I would check whether the destination is on the same subnet using `ip addr`. Then I would check `ip route` and use `ip route get 10.20.10.30` to see the next hop. Since the destination is on a different subnet, the traffic should go through the default gateway or a specific route. I would then check `ip neigh` to verify that the server can resolve the gateway's MAC address. If the gateway is reachable but the remote subnet isn't, I would investigate routing, ACLs, or firewalls. If the server cannot even reach its gateway, I would investigate Layer 2 issues such as VLAN, switch port, ARP, or the network interface.

## The 5 Commands to Memorise

```bash
ip -br addr
ip route
ip route get <destination>
ip neigh
ip link
```

And for deeper troubleshooting:

```bash
ping <destination>
traceroute <destination>
nc -zv <destination> <port>
tcpdump -i any host <destination>
```

## One-Line Interview Answer

> Switching forwards frames using MAC addresses within a Layer-2 network; routing forwards IP packets between different Layer-3 networks.
