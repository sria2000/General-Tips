# Git Interview Questions & Answers

> **Purpose:** Interview preparation for Linux, Infrastructure, SRE, DevOps and Platform Engineering roles.
>
> **Format:** Questions → concise interview answer → practical commands/examples.
>
> **Practice approach:** Start with Sections 1–3, then move to troubleshooting and advanced topics.

---

# 01. Git Fundamentals

## 1. What is Git?

**Answer:**

Git is a distributed version control system used to track changes to source code and other files.

Git provides:

* Version control
* Change tracking
* Branching
* Merging
* Collaboration
* History and rollback
* Distributed development

---

## 2. What is the difference between Git and GitHub?

**Answer:**

| Git                    | GitHub                          |
| ---------------------- | ------------------------------- |
| Version control system | Git repository hosting platform |
| Runs locally           | Cloud-based service             |
| Tracks file history    | Provides collaboration features |
| Open-source tool       | Commercial platform             |

Other Git hosting platforms include GitLab, Bitbucket and Azure Repos.

---

## 3. What is a Git repository?

**Answer:**

A Git repository is a directory containing project files and Git metadata used to track the project's history.

The Git metadata is stored under:

```bash
.git/
```

A repository can exist locally or remotely.

---

## 4. What does `git init` do?

**Answer:**

`git init` creates a new Git repository in the current directory.

```bash
git init
```

It creates the `.git` directory.

---

## 5. What is the `.git` directory?

**Answer:**

The `.git` directory contains Git's internal metadata, including:

* Commit history
* Branch information
* Repository configuration
* References
* Git objects

Deleting `.git` removes the Git repository metadata from that directory.

---

## 6. How do you check whether a directory is a Git repository?

```bash
git status
```

You can also check:

```bash
ls -la
```

and look for:

```text
.git
```

---

## 7. How do you configure your Git username?

Global configuration:

```bash
git config --global user.name "Sriram Varadharajan"
```

Repository-specific configuration:

```bash
git config user.name "Sriram Varadharajan"
```

---

## 8. How do you configure your Git email?

```bash
git config --global user.email "user@example.com"
```

Repository-specific:

```bash
git config user.email "user@example.com"
```

---

## 9. What is the difference between global and local Git configuration?

**Answer:**

Global configuration:

```bash
git config --global
```

applies to repositories for the current user.

Local configuration:

```bash
git config
```

applies only to the current repository.

---

## 10. How do you view Git configuration?

```bash
git config --list
```

Global:

```bash
git config --global --list
```

# 02. Git Working Areas

## 11. What are the three main areas in Git?

**Answer:**

```text
Working Directory
       ↓
Staging Area
       ↓
Local Repository
```

### Working Directory

Files you are currently modifying.

### Staging Area

Changes selected for the next commit.

### Local Repository

Committed Git history.

---

## 12. What is the staging area?

**Answer:**

The staging area is where you select changes that should be included in the next commit.

```bash
git add file.txt
```

---

## 13. What does `git status` do?

```bash
git status
```

It shows:

* Current branch
* Modified files
* Untracked files
* Staged changes
* Uncommitted changes
* Relationship with remote branches

---

## 14. What does `git add` do?

```bash
git add file.txt
```

Moves changes from the working directory into the staging area.

To stage everything:

```bash
git add .
```

---

## 15. What does `git commit` do?

```bash
git commit -m "Add application configuration"
```

Creates a snapshot of the staged changes in the local repository.

---

## 16. What is a Git commit?

**Answer:**

A commit is a snapshot of changes stored in Git history.

A commit contains information such as:

* Commit ID
* Author
* Timestamp
* Commit message
* Parent commit

---

## 17. What is a commit hash?

**Answer:**

A commit hash uniquely identifies a Git commit.

Example:

```text
a8f34d91c2e...
```

View commits using:

```bash
git log
```

---

## 18. How do you view Git history?

```bash
git log
```

Compact:

```bash
git log --oneline
```

Graphical:

```bash
git log --oneline --graph --decorate --all
```

---

## 19. What is `HEAD`?

**Answer:**

`HEAD` is a reference to the currently checked-out commit, normally the latest commit on the current branch.

```text
HEAD
 ↓
main
 ↓
Commit C
```

---

## 20. What is the difference between modified, staged and committed?

```text
Modified
   ↓
Working Directory

Staged
   ↓
Staging Area

Committed
   ↓
Git Repository
```

Example:

```bash
vim app.conf
git add app.conf
git commit -m "Update configuration"
```

# 04. Branches

## 26. What is a Git branch?

**Answer:**

A branch is a movable pointer to a sequence of commits.

Branches allow developers to work independently on:

* Features
* Bug fixes
* Experiments
* Releases

---

## 27. How do you list branches?

Local:

```bash
git branch
```

All branches:

```bash
git branch -a
```

---

```bash
git branch feature-login
```

---

Modern Git:

```bash
git switch feature-login
```

Older syntax:

```bash
git checkout feature-login
```


Older syntax:


```bash

```

Force:

```bash
git branch -D feature-login
```

---

## 32. How do you delete a remote branch?

```bash

```

---

## 33. Branch vs tag?

| Branch                | Tag                          |
| --------------------- | ---------------------------- |
| Normally moves        | Normally fixed               |
| Used for development  | Used for releases            |
| Tracks future commits | Identifies a specific commit |

## 34. What is a remote-tracking branch?

**Answer:**

A remote-tracking branch represents the last known state of a remote branch.

Example:

```text
origin/main
```

It is updated when you fetch from the remote.

# 05. Merge and Rebase

## 35. What is `git merge`?

**Answer:**

`git merge` combines changes from one branch into another.

```bash
git switch main
git merge feature-login
```

---

## 36. What is a merge conflict?

**Answer:**

A merge conflict occurs when Git cannot automatically reconcile changes, usually because different branches changed the same part of a file.

Git marks the conflict:

```text
<<<<<<< HEAD
Current branch
=======
Incoming branch
>>>>>>> feature-login
```

---

## 37. How do you resolve a merge conflict?

### Step 1

Check conflicts:

```bash
git status
```

### Step 2

Edit the conflicting files.

### Step 3

Stage the resolved files:

```bash
git add file.txt
```

### Step 4

Complete the merge:

```bash
git commit
```

---

## 38. What is `git rebase`?

**Answer:**

Rebase moves or reapplies commits onto another base commit.

```bash
git switch feature
git rebase main
```

It can produce a cleaner, linear history.

---

## 39. Merge vs Rebase?

### Merge

Preserves the original branch history.

### Rebase

Replays commits on top of another branch.

```text
Merge:

A---B---C-------M
     \         /
      D---E----


Rebase:

A---B---C---D'---E'
```

---

## 40. When should you avoid rebasing?

**Answer:**

Avoid rebasing commits that have already been shared with other developers because rebase rewrites commit history.

A good rule:

> Rebase private/unpublished work; be cautious about rebasing shared history.

---

## 41. How do you continue a rebase after resolving a conflict?

```bash
git add .
git rebase --continue
```

---

## 42. How do you abort a rebase?

```bash
git rebase --abort
```

---

# 06. Fetch, Pull and Push

## 43. What does `git fetch` do?

```bash
git fetch origin
```

Downloads changes from the remote repository without merging them into your current branch.

---

## 44. What does `git pull` do?

Typically:

```text
git pull
   =
git fetch
+
git merge
```

It downloads and integrates remote changes.

---

## 45. `git fetch` vs `git pull`?

```text
git fetch
    ↓
Download only
    ↓
Inspect changes
```

Whereas:

```text
git pull
    ↓
Download
    ↓
Integrate
```

For controlled troubleshooting, `git fetch` first is often preferable.

---

## 46. What does `git push` do?

Uploads local commits to the remote repository.

```bash
git push origin main
```

---

## 47. What does `git push -u origin main` do?

```bash
git push -u origin main
```

It:

1. Pushes the `main` branch.
2. Sets `origin/main` as the upstream branch.

---

## 48. Why does Git reject a push with "non-fast-forward"?

**Answer:**

The remote contains commits that the local branch does not have.

First:

```bash
git fetch origin
```

Then inspect the differences.

One possible solution:

```bash
git pull --rebase origin main
git push
```

---

## 49. What is a fast-forward merge?

**Answer:**

A fast-forward occurs when the target branch has no independent commits.

Git simply moves the branch pointer forward.

---

# 07. Undoing Changes

## 50. How do you discard working-directory changes?

```bash
git restore file.txt
```

---

## 51. How do you unstage a file?

```bash
git restore --staged file.txt
```

The changes remain in the working directory.

---

## 52. What is `git reset`?

**Answer:**

`git reset` moves `HEAD` and can also change the staging area and working tree.

Common options:

```bash
git reset --soft HEAD~1
git reset --mixed HEAD~1
git reset --hard HEAD~1
```

---

## 53. Explain `reset --soft`, `--mixed` and `--hard`.

| Option    | Commit | Staging | Working Files |
| --------- | ------ | ------- | ------------- |
| `--soft`  | Reset  | Keep    | Keep          |
| `--mixed` | Reset  | Reset   | Keep          |
| `--hard`  | Reset  | Reset   | Reset         |

**Important:** `--hard` can discard uncommitted work.

---

## 54. What is `git revert`?

**Answer:**

`git revert` creates a new commit that reverses an earlier commit.

```bash
git revert <commit-id>
```

It is generally safer for shared branches.

---

## 55. Reset vs revert?

```text
reset
  ↓
Changes existing history/reference

revert
  ↓
Creates a new commit
```

For shared production branches, `revert` is generally preferred.

---

## 56. How do you undo the last commit but keep the changes?

```bash
git reset --soft HEAD~1
```

---

## 57. How do you remove the last commit and its changes?

```bash
git reset --hard HEAD~1
```

**Warning:** This can permanently discard work.

---

## 58. What is `git stash`?

**Answer:**

```bash

```

---



---

## 61. `stash pop` vs `stash apply`?

```text
stash apply
    ↓
Apply stash
Keep stash

stash pop
    ↓
Apply stash
Remove stash
```

---

## 62. How do you stash untracked files?


1. Downloads repository data.

### SSH

```text
git@github.com:user/project.git
```

# 12. Advanced Git

## 81. What is `git cherry-pick`?

**Answer:**

Applies a specific commit to the current branch.

```bash
git cherry-pick <commit-id>
```

Useful when you need a particular fix without merging the entire branch.

---

## 82. What is interactive rebase?

```bash
git rebase -i HEAD~5
```

It allows you to:

* Reorder commits
* Squash commits
* Edit commit messages
* Drop commits
* Modify commits

---

## 83. What is Git squash?

**Answer:**

Squashing combines multiple commits into one.

```text
Commit A
Commit B
Commit C
```

becomes:

```text
Commit ABC
```

Useful for cleaning feature-branch history.

---

## 84. What is `git reflog`?

```bash
git reflog
```

Records movements of Git references such as `HEAD`.

It is extremely useful for recovering from:

* Accidental reset
* Rebase
* Deleted branches
* Lost commits

---

## 85. Can you recover a deleted commit?

**Answer:**

Often yes, if it has not been garbage-collected.

```bash
git reflog
```

Find the commit:

```bash
git branch recovery <commit-id>
```

---

## 86. What is `git bisect`?

**Answer:**

`git bisect` performs a binary search through Git history to identify the commit that introduced a bug.

```bash
git bisect start
git bisect bad
git bisect good <commit-id>
```

---

## 87. What is `.gitignore`?

**Answer:**

`.gitignore` specifies files that Git should not track.

Example:

```text
*.log
.env
node_modules/
*.tmp
```

---

## 88. Does `.gitignore` remove an already tracked file?

**Answer:**

No.

Remove the file from tracking:

```bash
git rm --cached file.txt
```

Then commit the change.

---

## 89. What is a Git hook?

**Answer:**

Git hooks are scripts executed automatically at specific points in the Git lifecycle.

Examples:

```text
pre-commit
commit-msg
pre-push
post-merge
```

They can be used for:

* Testing
* Linting
* Validation
* Security checks
* Commit message validation

---

## 90. What is a bare Git repository?

**Answer:**

A bare repository contains Git data but does not have a working directory.

It is commonly used as a server-side repository.

```bash
git init --bare project.git
```

# 13. Git Troubleshooting Scenarios

## 91. You accidentally committed a password. What do you do?

**Answer:**

First:

> **Immediately revoke or rotate the credential.**

Removing it from the latest commit is not enough because it may still exist in Git history.

Then remove the secret from history using an appropriate history-rewriting tool such as:

```text
git filter-repo
```

If the repository is shared, coordinate the history rewrite carefully.

---

## 92. Your local branch is behind the remote. What do you do?

First:

```bash
git fetch origin
git status
```

Then inspect the differences.

One possible approach:

```bash
git pull --rebase origin main
```

Then:

```bash
git push
```

---

## 93. You have uncommitted changes but need to switch branches.

**Answer:**

Use stash:

```bash
git stash
git switch another-branch
```

Later:

```bash
git stash pop
```

---

## 94. You pushed the wrong commit to a shared branch. What do you do?

**Answer:**

Avoid rewriting shared history unless there is a strong reason.

Use:

```bash
git revert <commit-id>
git push
```

This preserves the existing history.

---

## 95. A developer says their changes disappeared after `git pull`. How do you investigate?

Check:

```bash
git status
git branch
git log --oneline --all
git fetch --all
```

Then:

```bash
git log origin/main
```

and:

```bash
git diff HEAD origin/main
```

Confirm that the developer is on the correct branch.

---

## 96. What does "branches have diverged" mean?

**Answer:**

It means both local and remote branches contain commits that the other side does not have.

```text
        C---D local
       /
A---B
       \
        E---F origin/main
```

You need to integrate the histories using merge or rebase.

---

## 97. How would you troubleshoot a very large Git repository?

Check repository size:

```bash
git count-objects -vH
```

Investigate:

* Large binaries
* Build artifacts
* Generated files
* Large archives
* Accidentally committed files
* Long Git history

History cleanup may require:

```text
git filter-repo
```

---

## 98. What is Git LFS?

**Answer:**

Git LFS (Large File Storage) is an extension for managing large files outside normal Git object storage.

Common examples:

* Large binaries
* Videos
* Machine-learning models
* Large datasets

---

## 99. How do you troubleshoot Git authentication failures?

First check the remote:

```bash
git remote -v
```

For SSH:

```bash
ssh -T git@github.com
```

Check SSH keys:

```bash
ls -la ~/.ssh
```

Verbose troubleshooting:

```bash
ssh -vT git@github.com
```

For HTTPS, verify that the appropriate credential/token is configured and has sufficient permissions.

# 14. Git + CI/CD + DevOps

## 100. Explain a complete Git workflow in a real DevOps project.

**Answer:**

A typical workflow is:

```text
Developer
    |
    v
Clone Repository
    |
    v
Create Feature Branch
    |
    v
Make Changes
    |
    v
git status / git diff
    |
    v
git add
    |
    v
git commit
    |
    v
git fetch / rebase
    |
    v
git push
    |
    v
Pull Request
    |
    v
Code Review
    |
    v
CI Pipeline
    |
    +--> Build
    +--> Unit Tests
    +--> Security Scan
    +--> Linting
    |
    v
Merge to Main
    |
    v
CD Pipeline
    |
    v
Deployment
    |
    v
Monitoring / Validation
    |
    v
Release Tag
```

Typical commands:

```bash
git clone <repository>

cd <repository>

git switch -c feature/my-change

# Make changes

git status
git diff

git add .
git diff --staged

git commit -m "Implement my change"

git fetch origin
git rebase origin/main

# Resolve conflicts if required

git push -u origin feature/my-change
```

Then:

```text
Pull Request
     ↓
Code Review
     ↓
CI/CD
     ↓
Merge
     ↓
Deployment
```

# 18. Recommended Interview Practice Order

For a **Linux/SRE/Infrastructure Engineer** interview, practise in this order:

```text
01. Git Fundamentals
        ↓
02. Working Directory / Staging / Repository
        ↓
03. Initial Commit & Push
        ↓
04. Branches
        ↓
05. Merge & Rebase
        ↓
06. Fetch / Pull / Push
        ↓
07. Reset / Revert
        ↓
08. Stash
        ↓
09. Git History
        ↓
10. GitHub / SSH
        ↓
11. Advanced Git
        ↓
12. Troubleshooting
        ↓
13. Git + CI/CD
        ↓
14. Scenario Questions
```

## The key commands to be able to explain without hesitation

```bash
git init
git clone
git status
git add
git commit
git log
git branch
git switch
git merge
git rebase
git fetch
git pull
git push
git stash
git reset
git revert
git cherry-pick
git reflog
git diff
git show
git blame
```

> **Interview tip:** Don't just memorise what a command does. Be prepared to explain **why you would use it, what could go wrong, and how you would recover**. For Infrastructure/SRE interviews, scenario-based Git questions are often more valuable than simply remembering command syntax.
