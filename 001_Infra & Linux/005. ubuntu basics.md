# Ubuntu for RHEL/SUSE Administrators — Command Reference

A translation layer for admins coming from RHEL/SUSE into Ubuntu — mapping familiar tooling to Ubuntu/Debian equivalents and flagging the places where Ubuntu genuinely does things differently, not just with different command names.

---

## 1. Package Management (biggest mental shift)

| Task | RHEL/SUSE | Ubuntu |
|---|---|---|
| Install package | `yum`/`dnf install` / `zypper install` | `apt install` |
| Remove package | `yum remove` / `zypper remove` | `apt remove` (keeps config) / `apt purge` (removes config too) |
| Update all | `yum update` / `zypper update` | `apt update && apt upgrade` |
| Search | `yum search` / `zypper search` | `apt search` |
| List installed | `rpm -qa` | `dpkg -l` |
| Package info | `rpm -qi <pkg>` | `dpkg -s <pkg>` |
| What package owns this file | `rpm -qf <file>` | `dpkg -S <file>` |
| List files in package | `rpm -ql <pkg>` | `dpkg -L <pkg>` |
| Package format | `.rpm` | `.deb` |
| Install local file | `rpm -i pkg.rpm` | `dpkg -i pkg.deb` |
| Repo config location | `/etc/yum.repos.d/` | `/etc/apt/sources.list.d/` |

**Key gotcha:** `apt update` does **not** upgrade anything — it only refreshes the package index cache (equivalent to `yum makecache` / `zypper refresh`). This trips up a lot of RHEL admins who expect "update" to mean "apply updates."

```bash
apt update                      # refresh package index (NOT install updates)
apt upgrade                     # install available updates
apt full-upgrade                # like upgrade but can remove packages if needed (handles dependency changes)
apt install <pkg>
apt remove <pkg>
apt purge <pkg>                 # remove + config files
apt autoremove                  # clean up orphaned dependencies
apt list --installed
apt show <pkg>                  # like dnf/zypper info
apt-cache policy <pkg>          # shows installed vs available versions, which repo it'll come from
```

## 2. Service Management — Unchanged

Ubuntu uses systemd just like RHEL 7+/SUSE, so `systemctl`/`journalctl` work identically. No relearning needed here.

```bash
systemctl status <service>
systemctl restart <service>
systemctl enable <service>
journalctl -u <service> -f
```

## 3. Users, Sudo, and Root Access — Different Philosophy

Ubuntu's default philosophy is **no root login** — the first user is set up in the `sudo` group instead, and `root` has no password set by default (direct root login is disabled).

```bash
sudo -i                # get a root shell (equivalent to su - on RHEL, but via sudo)
sudo su -               # also works if you want the RHEL-familiar syntax
usermod -aG sudo <user> # add a user to the sudo group (RHEL equivalent: wheel group)
```

On RHEL you're used to `usermod -aG wheel`; on Ubuntu the equivalent group is **`sudo`**, not `wheel`.

## 4. Networking Config — Genuinely Different Tooling

Ubuntu (18.04+) uses **Netplan** as the default network configuration frontend, which renders to either `systemd-networkd` or `NetworkManager` underneath depending on install type (server vs desktop).

```bash
# Netplan config lives here (YAML, not ifcfg files or /etc/sysconfig/network)
/etc/netplan/*.yaml

# Apply changes
sudo netplan apply

# Test config without committing (rolls back automatically if not confirmed)
sudo netplan try

# Debug what netplan generated underneath
sudo netplan --debug apply
```

This is genuinely different from both RHEL's `nmcli`/ifcfg-scripts and SUSE's `wicked`/YaST networking approach — not just a renamed command.

```bash
# Ubuntu Server typically uses netplan → systemd-networkd
networkctl status
networkctl list

# If NetworkManager is in use instead (common on desktop, less so server)
nmcli device status
nmcli connection show
```

## 5. Firewall

```bash
# Ubuntu's default frontend is ufw (Uncomplicated Firewall), wrapping iptables/nftables
sudo ufw status
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw deny from <ip>

# RHEL equivalent: firewall-cmd / firewalld
# SUSE equivalent: firewalld or SuSEfirewall2 (older)
```

`ufw` is much simpler/less granular than `firewalld`'s zone model — no zones concept, just a straightforward allow/deny rule list. The underlying `iptables`/`nftables` is still there if you need to drop to that level directly.

## 6. Filesystem Layout Differences

| | RHEL/SUSE | Ubuntu |
|---|---|---|
| Web server default | Apache: `/etc/httpd/` | Apache: `/etc/apache2/` |
| Web root | `/var/www/html/` | `/var/www/html/` (same) |
| Apache config style | Monolithic `httpd.conf` | Modular `sites-available/`, `sites-enabled/`, `mods-enabled/` |
| Cron | `/etc/cron.d/`, `crontab -e` | Same, plus heavier use of `/etc/cron.daily/` etc. |
| Init scripts (legacy) | `/etc/init.d/` (mostly gone now) | `/etc/init.d/` still present as compatibility shims over systemd |

**Apache's modular config is a genuinely different workflow:**

```bash
a2ensite <site>        # enable a site config
a2dissite <site>       # disable a site config
a2enmod <module>       # enable a module
a2dismod <module>      # disable a module
systemctl reload apache2
```

## 7. Kernel / GRUB

```bash
# Update GRUB config after kernel or boot param changes
sudo update-grub                    # Ubuntu-specific wrapper
# RHEL/SUSE equivalent: grub2-mkconfig -o /boot/grub2/grub.cfg

# List installed kernels
dpkg --list | grep linux-image

# Remove old kernels (Ubuntu tends to accumulate these over time)
sudo apt autoremove --purge
```

## 8. AppArmor vs SELinux — Conceptual Difference, Not Just Naming

Ubuntu defaults to **AppArmor**, not SELinux. This is worth knowing cold — it comes up often in "secure this Ubuntu server" style questions.

```bash
sudo aa-status                              # like sestatus on RHEL
sudo aa-enforce /etc/apparmor.d/<profile>
sudo aa-complain /etc/apparmor.d/<profile>  # like setenforce permissive, but per-profile
```

**The conceptual distinction to state explicitly if asked:** AppArmor is **path-based** — profiles reference file paths directly. SELinux is **label-based** — every file/process gets a security context/label independent of its path, and policy decisions are made against those labels. Path-based is simpler to reason about; label-based is more robust against things like symlink tricks or files moving around, at the cost of more upfront complexity (contexts, `semanage`, relabeling).

## 9. Ubuntu-Specific Utilities Worth Knowing

```bash
lsb_release -a          # distro version info (works elsewhere too, but very Ubuntu-idiomatic)
do-release-upgrade      # major version upgrade (e.g. 22.04 → 24.04) — no direct RHEL equivalent; RHEL major upgrades are a bigger, separate operation
update-alternatives     # manage symlink alternatives for commands with multiple providers (exists on RHEL too, less commonly used there)
snap list                # Ubuntu's own containerized package format, separate from apt/.deb entirely
cloud-init status        # heavily used on Ubuntu cloud/server images for first-boot provisioning
```

`cloud-init` is worth flagging specifically for bare-metal/provisioning-focused roles — Ubuntu Server images lean on it heavily for PXE/MAAS-driven automated setup, conceptually similar to how kickstart works on RHEL, but YAML-based and cloud-native in origin. Relevant given MAAS itself is Canonical's tool and defaults to Ubuntu + cloud-init for the deployment stage.

## Quick Reference Card — Side-by-Side Cheat Sheet

| Task | RHEL/SUSE | Ubuntu |
|---|---|---|
| Install a package | `dnf install` / `zypper install` | `apt install` |
| Refresh repo metadata | `dnf makecache` / `zypper refresh` | `apt update` |
| Apply updates | `dnf update` / `zypper update` | `apt upgrade` |
| Query installed package | `rpm -qi` | `dpkg -s` |
| Which package owns a file | `rpm -qf` | `dpkg -S` |
| Elevate to root | `su -` | `sudo -i` / `sudo su -` |
| Admin group | `wheel` | `sudo` |
| Network config | `nmcli` / ifcfg files / wicked | `netplan` (YAML) |
| Firewall | `firewall-cmd` (zones) | `ufw` (simple allow/deny) |
| Mandatory access control | SELinux (label-based) | AppArmor (path-based) |
| Apache config style | Monolithic `httpd.conf` | Modular, `a2ensite`/`a2enmod` |
| Update bootloader config | `grub2-mkconfig` | `update-grub` |
| Major version upgrade | New install / `leapp` (RHEL) | `do-release-upgrade` |
